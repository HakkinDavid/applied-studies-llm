1. Introducción al refactoring
●El refactoring consiste en una serie de pasos
pequeños, cada uno de los cuales cambia la
estructura interna de un programa sin cambiar su
comportamiento externo.
●Para verificar que no haya cambios en el
comportamiento externo se utilizan:
● Pruebas
● Herramientas para el análisis formal de código
Introducción al refactoring (2)
●De donde viene:
● Ward Cunningham y Kent Beck
●El estilo Smalltalk
● Ralph Johnson, University of Illinois at Urbana-Champaign
● La tesis de Bill Opdyke
● John Brant y Don Roberts
●“The refactoring browser”
Introducción al refactoring (3)
●Metáfora básica:
● Iniciar con el código existente y mejorarlo
●Definición formal:
● El proceso de cambiar un sistema de software tal que:
●El comportamiento externo no cambia
●La estructura interna del sistema se mejora
●Meta:
● Hacer el software mas fácil de entender y de modificar
Introducción al refactoring (4)
●Los administradores odian el refactoring
● “Si los programadores dedican mas tiempo a limpiar el
código, dedican  menos tiempo a implementar la
funcionalidad”
●También se puede mejorar el código de manera
significativa:
● Reduciendo el código muy parecido
● Mejorando el entendimiento, comunicando la intención
● Mejorando la cohesión
● Mejorando la parametrizacion, mantenimiento, flexibilidad,
abstracción, eficiencia, etc.
Introducción al refactoring (5)
●La referencia obligada:
Fowler, M. Refactoring: Improving the design of existing

Introducción al refactoring (6)
●El libro contiene ideas que han estado en el
ambiente desde hace mucho tiempo.
●Sobre todo, este libro es un catalogo de
transformaciones que se pueden aplicar a nuestro
código.
● 22 “(malos) olores” (antipatrones)
● 72 “refactorizaciones” (que hacer al encontrar los malos

Introducción al refactoring (7)
●Cuando se debe hacer refactoring ? Que tan
seguido ? Cuanto tiempo se debe dedicar ?
●No es algo a lo que se dediquen dos semanas
cada seis meses … mas bien, se hace mientras
se desarrolla.
●Se hace refactoring cuando se reconoce algún
signo de alerta (olor) y se sabe que hacer.
Introducción al refactoring (8)
●La regla de tres:
●La primera vez que codifique una tarea, solo
hágala.
●La segunda vez que codifique la misma idea,
aguante y codifíquela de nuevo.
●La tercera vez que codifique la misma idea, es
tiempo de hacer refactoring.
Introducción al refactoring (9)
●Antes de hacer refactoring:
●Recuerde que el propósito es “cambiar la
estructura interna preservando la semántica”
●Cómo sabremos que se preserva la semántica ?
●Al hacer cambios se pueden introducir errores.
●Se debe tener un conjunto solidó de pruebas para las
secciones a las que se haga refactoring.

Movimiento de un método (move
method)
● Un método es, o será, utilizado mas por otra clase que por su clase misma.
● Crear un nuevo método con un cuerpo similar, en la clase donde se utiliza mas.
● Modifique el método viejo para que sea una delegación simple o remuévalo.
Pasos para el movimiento de un método
● Declare el método en la clase objetivo.
● Copie y ajuste el código.
● Agregue una referencia del objeto fuente al objetivo.
● Convierta el método original en un método delegado.
● amountOf(Rental each) { return each.charge()}
● Verifique los métodos sobrecargados.
● Compile y pruebe
● Encuentre a todos los usuarios del método.
● Ajústelos para que invoquen al método objetivo.
● Remueva el método original.
● Compile y pruebe.

Reemplazo de código de tipo a través
del patrón de estado/estrategia
● Se tiene un código de tipo que afecta el comportamiento de
una clase, pero no se pueden utilizar subclases.
● Remplazar el código de tipo con un objeto de estado.
Pasos para reemplazar un código de tipo a
través del patrón de estado/estrategia
● Cree una nueva clase de estado para el código de tipo.
● Agregue subclases de la clase estado para cada tipo.
● Cree una consulta abstracta en la superclase para regresar el
tipo y sobrescriba en las subclases para regresar el tipo
correcto.
● Compile.
● Cree un campo en la clase vieja para el objeto de estado.
● Cambie la consulta del tipo para delegar hacia el objeto de
estado.
● Cambie los métodos que asignan los tipos para que asignen
instancias de las subclases.
● Compile y pruebe.

Método plantilla
● Se tienen dos métodos, en dos subclases, que llevan a cabo
pasos similares en el mismo orden, sin embargo son
diferentes.
● De a cada paso en los métodos la misma firma, de tal manera
que los métodos originales se conviertan en el mismo.
Pasos para el método plantilla
●Tome dos métodos con estructura similar, pero
variación en algunas partes.
● Use subclases de la clase o cree una estrategia y mueva
los métodos a la estrategia.
●En cada variación extraiga los métodos que tengan
la misma firma, pero cuerpo diferente.
●Declare la firma de los métodos extraídos en una
superclase y coloque la variación  en subclases.
●Cuando se hayan removido los puntos de variación,
mueva un método fuente a la superclase y remueva
el otro.
